# 复旦MBA 凤凰3班：飞书接入与上线

网站已准备好飞书读取接口、五张表的模板，以及“前往飞书维护”页面。Banner 已加入“橙启新序，共赴同行”。目前还没有你的飞书表格和应用凭证，因此尚未进行真实飞书连接，也尚未发布这一版在线网站。

按下面顺序操作。你现在只需要先完成第一步，把表格链接发回这段对话；应用密钥不要发送到聊天中。

## 第一步：新建班级多维表格

1. 打开飞书，进入云文档，新建“多维表格”。名称建议为“复旦MBA 凤凰3班｜班级信息”。先创建独立多维表格，网址含 `/base/`，便于首次配置。
2. 解压模板包，在同一个多维表格里，从本地导入五个 CSV 文件，每个文件成为一张数据表。选择“第一行作为字段名”。若导入入口要求选择目标，选择新建数据表，不要把五份数据合并成一张表。
3. 将五张表分别命名为“课程”“作业”“活动”“公告”“资料”。表名可改，但列名必须保留模板中的写法。
4. 先保持示例记录为“草稿”。按照模板包的《先读这里》设置字段类型，并替换示例内容。
5. 在分享设置中邀请负责维护的同学，给他们编辑权限。普通浏览者无需获得表格编辑权限。
6. 复制多维表格链接发给我。这个链接用于配置维护入口；发链接本身不会授权网站读取内容，仍需下面的应用权限。

## 第二步：建立只读飞书应用

这部分一般由飞书组织管理员或有自建应用权限的同学操作。若账号无法创建或发布自建应用，请请组织管理员协助；不用改动表格内容。

1. 打开 [飞书开放平台](https://open.feishu.cn/app)，创建企业自建应用，名称可用“凤凰3班网站”。
2. 在“权限管理”申请应用身份的以下权限：`base:record:retrieve`（根据条件搜索记录）和 `base:field:read`（获取字段信息）。也可使用覆盖这两项的 `bitable:app:readonly`（查看、评论和导出多维表格）；无需申请新增、修改、删除记录权限，也无需通讯录权限。
3. 在“版本管理与发布”创建版本并发布。若组织要求管理员审核，等待审核通过。权限修改后也要发布新版本。
4. 返回多维表格，在“更多 / 添加文档应用”一类入口中添加刚才的应用，授予读取这五张表所需的文档权限。应用接口权限和文档访问权限都要完成。
5. 第一版可使用普通共享权限。如果开启了多维表格高级权限，还需要核对应用能读取五张表的全部预期记录；官方提示，高级权限不足可能返回空记录。不要把空结果误判为连接正常。
6. 在应用“凭证与基础信息”找到 App ID 和 App Secret。App Secret 只填到发布平台的环境变量，不要放进网页文件、CSV、GitHub 或聊天。

## 第三步：取得表格标识

分别打开五张数据表，查看地址栏。普通独立多维表格的网址通常是：

`https://你的组织.feishu.cn/base/多维表格标识?table=某张表的标识&view=视图标识`

`/base/` 后面的部分是整个多维表格的标识，对应 `FEISHU_BASE_TOKEN`；`table=` 后面的部分是当前数据表的标识。五张表各有一个不同的标识。`view=` 不是数据表标识。

如地址是 `/wiki/`，不要直接把 wiki 标识当作 Base Token；需要额外解析知识库节点。首次接入建议使用第一步新建的独立多维表格。

## 第四步：发布完整网站与后台

上一版“只拖拽 dist 文件夹”的方法仅发布网页，不能部署此次增加的飞书读取后台。此版按 GitHub → Netlify 的方式发布整个项目。

1. 解压“凤凰3班-飞书接入版源码.zip”。里面应有 `dist`、`server`、`netlify` 文件夹，以及 `netlify.toml`、`package.json` 等文件。
2. 在 [GitHub](https://github.com/new) 创建一个你管理的仓库，建议设为 Private。上传解压后的项目内容，仓库第一层应直接看到 `netlify.toml` 和 `package.json`。不要只上传 dist，也不要把整个项目再多套一层目录。`.env.example` 仅是空白配置样例，可上传；本地 `.env` 和任何真实密钥都不要上传。
3. 登录 [Netlify](https://app.netlify.com/login)，选择从现有项目或 Git 导入，连接 GitHub，选中刚才的仓库。将 GitHub 授权限定到这个仓库即可。
4. 使用仓库中的 `netlify.toml`。如页面要求确认设置：Base directory 留空，Build command 为 `npm run check`，Publish directory 为 `dist`，Functions directory 为 `netlify/functions`。
5. 首次部署完成但未配置飞书时，网页显示“尚未连接飞书 · 当前为示例内容”。这是预期状态。
6. 在项目设置的 Environment variables 中添加下表变量。变量需要覆盖 Production 环境，并且作用域包含 Functions；如果可选标记，App Secret 标为密钥。
7. 保存后重新部署。环境变量变更需要新部署才能在函数运行时生效。

| 变量名称 | 填入内容 |
| --- | --- |
| FEISHU_APP_ID | 自建应用的 App ID |
| FEISHU_APP_SECRET | 自建应用的 App Secret，只存发布平台 |
| FEISHU_BASE_TOKEN | 整个多维表格的标识 |
| FEISHU_TABLE_COURSES | “课程”表的 table 标识 |
| FEISHU_TABLE_ASSIGNMENTS | “作业”表的 table 标识 |
| FEISHU_TABLE_ACTIVITIES | “活动”表的 table 标识 |
| FEISHU_TABLE_NOTICES | “公告”表的 table 标识 |
| FEISHU_TABLE_RESOURCES | “资料”表的 table 标识 |
| FEISHU_BASE_URL | 维护同学打开的完整飞书多维表格 HTTPS 链接 |

前八项用于读取，必须全部填写。最后一项用于“前往飞书维护”按钮。无凭证时展示明确标注的示例；只填一部分时会显示配置未完成，避免把示例误认成正式内容。

## 第五步：验证同步，再分享

1. 在“公告”表新增一条内容，例如“网站连接测试”，填完整标题、正文、发布人、发布时间，状态为“草稿”。确认网页没有这条公告。
2. 将这条记录改为“已发布”。几分钟后刷新网站，确认顶部显示“飞书已同步”，并出现这条公告。所有草稿都为空时，正式网站显示空列表，不会混入演示数据。
3. 修改公告标题，再验证网站更新。测试完将其改为“已下架”，确认网站中消失。
4. 再用一条课程、作业、活动、资料检查：课程日期、作业倒计时、活动参加人数与对接人、资料链接。资料链接的访问权限由飞书文档本身决定，网站免登录不代表所有资料都能免登录打开。
5. 确认各表的已发布记录数量与网站一致。维护页若提示无效记录，检查必填项、时间格式、活动起止顺序、人数及资料 HTTPS 链接。
6. 如果要让同学免登录访问网站，在 Netlify 项目中选择 Make public；这会让拥有链接的人都能访问。用手机或浏览器无痕窗口打开网站确认，再发到班级群。不要只用已登录 Netlify 的窗口判断别人能否访问。

同步说明：后台结果缓存5分钟；打开的网页每5分钟检查一次，回到页面或点击“检查更新”也会重新检查。两层间隔叠加，新增与撤回最长可能约10分钟后反映。没有声称实时推送。连接失败时网站会清空本次未核实的内容并提示重试，不会冒充为最新信息。

## 以后怎样维护

班级同学只在飞书中编辑。补齐内容后改为“已发布”，需要撤回则改为“草稿”或“已下架”。更改表格记录不用重新部署；修改网站样式、代码或后台环境变量才需要重新部署。

课程、作业、资料的课程代码应一致，方便关联。活动人数由维护同学填写；网站没有个人报名或作业勾选。网站只展示五张表中预设的公开字段。成员通讯录和学习小组没有接入这五张表，正式模式下不会展示原型中的虚构同学名单。

## 常见问题

| 看到的情况 | 应检查什么 |
| --- | --- |
| 尚未连接飞书，示例内容 | 是否把变量配置在 Functions 作用域，且重新部署 |
| 配置尚未完成 | 前八个变量是否全部填写，变量名是否完全一致 |
| 飞书读取失败 | App ID / Secret、应用发布审核、接口只读权限、添加文档应用 |
| 表格列名不一致 | 是否把五张表标识填反，是否改名或删除了模板列 |
| 已同步，但全为空 | 是否仍为草稿；若已发布，核对高级权限及应用可读取范围 |
| 有无效记录未显示 | 日期/时间格式、必填项、活动结束早于开始、人数、资料链接 |
| 网站打开但无法同步 | 是否仅上传了 dist；是否成功部署 class-content 函数 |
| 同学打开要求 Netlify 登录 | 项目是否仍为 Private |
| 资料链接要求飞书登录 | 资料自身分享权限，不是网站登录功能 |
